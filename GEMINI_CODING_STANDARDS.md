# MySitter — Gemini Coding Standards

This document contains the official coding standards and best practices for the MySitter project. All code generated by Gemini must adhere to these rules.

---

## General Rules

1.  **`enabled` guard on every conditional query**: Any `useQuery` that should only fire for certain roles, states, or conditions MUST pass an explicit `enabled: <boolean expression>` parameter. **Never** rely on error-handling (`onError`, status checks) to suppress requests that should not be made.

2.  **Import hygiene after deletions**: When a method is removed from a service, **simultaneously** remove every import of that method in every file that referenced it (routers, tests, other services).

3.  **Verify field existence before use**: Before referencing any field on a typed object (e.g., `booking.provider_display_name`), **confirm the field exists** in the TypeScript type in `packages/types/src/index.ts` or the Pydantic schema.

4.  **No stub `onClick`/`onPress` handlers**: Every `onClick`/`onPress` must be fully implemented. If a feature is not yet ready, either disable the button (`disabled={true}`) or remove it from the JSX.

5.  **Presigned URL content-type must match actual file**: When calling the upload presign endpoint, pass the **actual file's content type** from `file.type`. Never hardcode `"image/jpeg"`.

6.  **All imports must be used**: Every imported hook, component, or value must appear in the component body or return block.

7.  **Match all JSX opening/closing tags**: Triple-check every closing tag matches its opening tag exactly, including casing.

8.  **`ApiClient` namespaces are class properties**: When adding a namespace to `ApiClient`, declare it as a **class property with an object literal**, not as a method returning an object.

9.  **Mobile uses relative imports only**: `apps/mobile` has no `@/` path alias configured. Every import in a mobile file must use a relative path.

10. **SQLAlchemy 2.x count queries**: Always use `select(func.count()).select_from(Model)` or `select(func.count()).select_from(query.subquery())`.

11. **No bare `pass` for stub implementations**: Always use `raise NotImplementedError("not yet implemented")`.

12. **Account for all downstream resource creation**: Registration and creation flows must account for all downstream resource creation.

---

## Python (apps/api)

*   Always use type hints on function signatures and class attributes.
*   Prefer OOP over procedural — use classes to encapsulate related state and behavior.
*   Follow PEP 8: `snake_case` functions/variables, `PascalCase` classes, `UPPER_CASE` constants.
*   Use SQLAlchemy 2.x `Mapped`/`mapped_column` style throughout.
*   Business logic lives in `services/`, not in routers.
*   Validate at boundaries (routers/schemas); trust internal code.
*   Async throughout: `async def` routes, async SQLAlchemy sessions, async Redis.

---

## TypeScript (apps/web, apps/admin, apps/mobile, packages/)

*   Strict TypeScript (`"strict": true` in tsconfig).
*   API response types come from `packages/types` — never redeclare them locally.
*   Use TanStack Query for all server state — no manual `useEffect` data fetching.
*   Components own UI only; data fetching via custom hooks in `hooks/`.

---

## Database Abstraction

*   **Repository pattern**: data access lives in repository classes (e.g. `UserRepository`, `BookingRepository`) with well-defined method signatures.
*   **Dependency-injected sessions/connections**: pass the DB session or connection into repositories via constructor or function parameter.
*   **No provider-specific leakage into business logic**.
*   **Abstract base or protocol**: define an abstract base class or `Protocol` for each repository.
*   This applies to every persistence store, not just the primary DB.
